# v3《鼎革》视觉化计划 —— 让数字变成看得见的东西

> 目标：把 v3 从「一屏文字」变成有君王、有军队、有疆域的东西，
> 同时**不牺牲它现在最大的优势**——一只手、随时能停、8 分钟一局。

---

## 一、为什么把重心放在 v3

回看最初的需求：**「下班很累，在地铁上玩」**。

| | v1/v2 幸存者 | v3 文字 |
|---|---|---|
| 操作 | 两只手 | 一只手 |
| 注意力 | 12 分钟不能断 | 随时可以停 |
| 被打断 | 直接死 | 无所谓（回合制） |
| 竞品 | Vampire Survivors / Brotato / Survivor.io，几十款，多款有大预算 | 《王权》(Reigns) 系列主导，长尾较薄 |

**v3 才是最贴合那个原始需求的游戏**，而且机制层已经打磨得足够深
（12 位君王、解锁、六种资源、朝堂加成、军需、107 个手写事件、7 种结局）。
它现在缺的只有一样：**它看起来还是一屏字。**

### ⚠️ 关于竞品，一处需要修正的判断
本文件初稿写过「中文朝代文字 roguelite 几乎没有竞品」——**这是错的**。

- **Reigns: Three Kingdoms**（Nerial）背景就是**汉末**，玩家从平民爬到皇帝/女帝，
  与 v3 的核心概念几乎重合。
- **Reigns**（2016, Devolver）是这一类型的开创者：资源条 + 左右滑动抉择 +
  **死后由继承人接位、解锁跨局保留**。中文版早已存在。
- 《人生重开模拟器》（2021）在中文圈爆火并催生大批模仿者，
  说明中文文字 roguelite 的受众已被喂过。

准确的说法是**「拥挤程度差一个量级」**，不是「没有竞品」。
但推荐 v3 的三条理由（贴合需求 / 机制已深 / 扩展便宜）**没有一条依赖「没有竞品」**，
所以结论不变。另外本项目的 LICENSE 写明仅供游玩，不是要上架的商业产品，
竞品格局对「自己玩得爽不爽」的影响本来就有限。

v1/v2 的问题不是画面，是玩法本身（见 `Plan/v1v2-fun.md`），不在本计划范围内。

---

## 二、核心原则：把数字变成图，不是加插画

这是整份计划最重要的一条。

> **装饰性插画，玩家第二局就不看了。**
> **跟着数值变化的图，每一回合都在被感知。**

所以每一张图都必须挂在一个**会变的数值**上。凡是「画得好看但从不变化」的，
优先级一律往后排。

## 三、六个视觉层（按性价比排序）

### ① 军容 —— 最值的一项 ⭐
把「兵力 64」画成**一排士兵剪影**，每 10 兵一个人形。
折损 20 兵，两个身影当场淡出并红闪一下。一个数字从此变成一件能看见的事。

- 上限显示 15 个人形（对应 `rules.ts` 里 `ratio()` 给兵力设的天花板 150）
- **顺带解决一个现存问题：军制第一次变得可见**。
  现在「江南水师」只是侧栏一行小字，改后是一排船；
  农民军是褴褛的、边军骑兵是骑马的、火器新军扛鸟铳、亲军精锐是甲士。
- 资源：5 张剪影（每种军制一张），可合成一张 sprite sheet
- 数据源：`run.army`、`run.armyType`（都已存在，无需改机制）

### ② 君王立绘（12 张）
大厅从文字方块变成立绘阵列；局内 topbar 放一张小图。

- **锁住的君王用剪影** —— 同一张图加 `filter: brightness(0) opacity(.35)` 即可，
  **不需要画第二套**。效果也比现在的 🔒 好得多：你能看见那里站着一个人，只是还没见到。
- 数据源：`MONARCHS[].name`、`meta.unlocked`

### ③ 舆图
现在城池是 2×5 的文字格，完全没有「战线在推进」的感觉。

- 一张写意中国底图 + 10 个城池按地理位置绝对定位
- 已得城池染朱红，都城盖一枚印
- **「四座城」从一个计数器变成一幅图** —— 而那正是「万世之基」结局的门槛
- 数据源：`run.cities`、`run.city`；替换现有 `.map-grid`

### ④ 事件分类卡头（约 11 张）
107 个事件不可能一张张画。但事件的 `source` 字段已经带了分类，
`App.tsx` 里也已经在用 `run.event.source.split(' · ')[0]`。

⚠️ **但不是免费的**：实际统计下来有 **24 种前缀**，不是 10 种。需要先做一次归并：

| 归并后 | 现有前缀 | 事件数 |
|---|---|---|
| 正统 | 正统、天命、开国、终局 | 22 |
| 军情 | 军情、战略、军心、军纪 | 13 |
| 民政 | 民政、流民、官府、民变、内廷 | 12 |
| 人才 | 人才 | 10 |
| 外交 | 外交、谋略、教门 | 10 |
| 死生 | 死生 | 9 |
| 财富 | 财富 | 7 |
| 军制 | 军制 | 7 |
| 婚姻 | 婚姻 | 6 |
| 城池 | 城池 | 6 |
| 天灾 | 天灾 | 6 |
| （阶段挑战单独处理） | 阶段挑战 | 5 |

归并放在**新文件**里做一张映射表，不改事件文案本身（避免与 tim.lu 冲突）。

- 形式：**卡头横幅**，不是整幅插画 —— 文字仍是主角，加载也快

### ⑤ 结局画（7 张）
万世之基 / 马上得天下 / 民心所归 / 万邦来朝 / 乱世吞没了你 / 天命未成 / 中道崩殂。
**这是玩家会截图分享的那一屏**，值得单独下功夫。

### ⑥ 朝堂人物（11 张小头像）
人才从文字 chip 变成头像 chip。优先级最低，但很便宜。

## 四、美术风格与生产

**推荐风格：明代木刻版画 / 水墨线稿。** 四个理由：

1. 贴题材
2. **线稿能掩盖 AI 生成的不一致** —— 12 张脸风格统一是这整件事最大的风险
3. 文件极小（有限色板，压缩率高）
4. 小尺寸在手机上仍然清楚

而且它天然吻合现在的宣纸 + 朱砂配色（`#efe1c4` / `#a52d26`），不用重做 UI 配色。

**生产流水线**（已有，做英雄立绘时建的）：
AI 生成 → `rembg` 抠背景 → 统一色调 → 导出 webp → 放 `public/arts/`

**体积预算**（AGENTS.md 有「大图别提交」的硬约束）：

| 类别 | 张数 | 单张 | 小计 |
|---|---|---|---|
| 君王立绘 | 12 | ~50KB | 600KB |
| 结局画 | 7 | ~50KB | 350KB |
| 分类卡头 | 11 | ~25KB | 275KB |
| 舆图 | 1 | ~80KB | 80KB |
| 军容剪影 | 5 | ~10KB | 50KB |
| 人才头像 | 11 | ~8KB | 88KB |
| **合计** | **47** | | **≈1.4MB** |

1.4MB 可接受，但**结局画与分类卡头应懒加载**（首屏只需要立绘 + 军容）。

## 五、几乎不花钱的两件事

**动效** —— 文字游戏显得死，是因为什么都不动。纯 CSS/JS，无需资源：
- 数值滚动跳变 + 变色闪一下
- 盖章动画（决定落下时「诏」印盖上去）
- 危机时红色暗角 + 轻微震屏
- 军容人形的淡入淡出

**音效** —— 照搬 v2 的思路（`src/game2/game/audio.ts` 是程序化 Web Audio 合成，
零音频文件、可离线）：盖章声、战鼓、危机铜锣。**复用做法，不复用文件**
（三个游戏互不 import 是本仓库的既定结构）。

| 阶段 | 内容 | 目的 |
|---|---|---|

## 七、技术约束

- **v3 是纯 DOM/CSS 渲染，不是 canvas** —— 加图就是 `<img>` + CSS，
  不涉及 v1/v2 那套贴图加载 / 帧动画 / canvas blit / 朝向翻转。**这是 v3 的优势。**
- `public/arts/` 三个游戏共用，构建已经会拷贝，**不用改构建**
- 不需要任何新依赖
- 原始素材放 `art-source/`（已 gitignore），**只提交压缩后的 webp**
- 新增代码进新文件（如 `src/game3/art.ts` 放映射表），`App.tsx` 只做最小接入 ——
  与 tim.lu 并行开工时冲突面最小

## 八、验收

- `npx tsc --noEmit && npm run build` 全绿
- Playwright 无头：截图大厅立绘阵列（含锁住的剪影）、军容随兵力增减、
  舆图城池点亮、各结局画；断言无 `pageerror` / console error
- **图片体积回归**：`dist/` 总大小不超过约 3MB
- 手机实机看一眼：立绘在小屏上是否还认得出、卡头是否喧宾夺主

## 九、从《王权》(Reigns) 学到的两条（机制，不是视觉）

查竞品时捡到的，与本计划并行，属于 `game3-improvements.md` 的后续：

### ① 死亡不该是死胡同
Reigns 里君王死后由**继承人接位**，故事继续。
v3 现在的「中道崩殂」是一堵纯粹的墙——一屏字、没有结局、没有解锁、整局白打，
而它触发概率是 30%，惩罚过重。

改法：**太子继位**。继承部分资源（兵力/粮草打折保留）、**威望清零**（新君没有名分）、
事件继续推进，起居注记一笔。惩罚从「作废」变成「重创 + 叙事」。

### ② 资源两头都该要命
Reigns 的四条资源在 **0 和满** 都会让你下台（教权太盛，教会反过来废了你）。
v3 现在只在低位触发危机——民心 100、兵力 200 都毫无代价，
于是最优解永远是「某项越高越好」。

改法：给高位也加风险。例如
- 兵力过高 → 将领拥兵自立（稳定下降）
- 威望过盛 → 功高震主 / 树大招风
- 稳定过高 → 政令僵化，民心与人才流失

六种资源会立刻从「越多越好」变成「要平衡」，抉择的重量整体上一个台阶。
⚠️ 这会显著改变平衡，**必须重跑随机乱选基准**（当前 45 局 ≈ 38% 胜率）。

## 十、风险

| 风险 | 应对 |
|---|---|
| 12 张立绘风格不统一（最大风险） | 阶段 0 先定风格；选线稿类风格，容错高 |
| 图片喧宾夺主，反而不好读 | 卡头用横幅不用整图；文字始终是主角 |
| 体积拖垮推送 | 只提交 webp；结局画与卡头懒加载 |
| 加了图但没变好玩 | 严守「图必须挂在会变的数值上」；纯装饰的一律后排 |
