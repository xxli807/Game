# 鼎革 · 逐鹿：三路推塔对战

## 起因与取舍

用户想要「王者荣耀那样的形式和打法」。能做与不能做的边界：

- **不做真人联机**：站点是 GitHub Pages 静态托管，没有服务器，匹配与同步都无从谈起。
- **做单机 5v5**：玩家操控一位君王，四名 AI 友军、五名 AI 敌将，三条兵线、防御塔、小兵、野怪、基地。
- **只取品类通则，不抄任何具体设计**：兵线 / 防御塔 / 三技能加大招 / 回城 / 推荐装备是 MOBA 通则；
  十二位君王的技能、名称、数值、装备、界面布局与美术全部原创，不使用任何受版权保护的角色、技能名、图标或版式。
- **作为第三个入口**（用户确认），与文字抉择、3D 亲历并列；不改动王朝玩法。

## 结构

全部在 `src/game3/arena/`，不 import 王朝流程，只借用 `action/` 的骨骼角色（`makeWarrior` / `loadHumans`）。

| 文件 | 职责 |
|---|---|
| `data.ts` | 地图几何（沿河道 y = x 镜像）、十二位君王的技能表、装备、出装、难度。纯数据 |
| `sim.ts` | 整局规则：`ArenaSim.step(dt)`。无 DOM、无 three.js、固定种子即确定性——可在 node 里几秒跑完一整局 |
| `render.ts` | three.js 渲染：固定朝北镜头（己方基地恒在左下）、英雄用共享骨骼角色、小兵 / 弹道 / 血条全部实例化 |
| `game.ts` | 一局的控制器：定步长推进、键鼠与触屏输入、把事件变成播报与音效、每 0.1 秒给 React 一份 HUD 快照、小地图 |
| `Arena.tsx` / `arena.css` | 赛前说明（选君王、看技能、选难度）、对战 HUD、结算 |
| `sound.ts` / `record.ts` | 程序化音效；战绩存档 `dingge:v3:arena`（不改 `meta.ts` 的结构） |

`App.tsx` 的接入点只有：`arena` 状态、`finishArena`（记战绩、胜利时解锁下一位君王）、一行提前返回。

## 规则要点

- 推掉**任意一路的两座塔**后敌方大鼎才可被攻击；击毁大鼎获胜。
- 塔与鼎在**没有己方小兵在场时只受 30% 伤害**，并优先攻击小兵；在塔下打敌将会被塔转火，且塔对英雄连续命中伤害递增。
- 兵线每 22 秒一波（3 近战 + 1 远程，每两波加一辆攻城车）；小兵随时间成长，8 分钟后加速成长以防僵局；
  破掉一路两塔后该路己方兵线强化。
- 等级上限 15，4 级解锁大招；技能随等级与攻击力成长，无需手动加点。金币可随地购买，HUD 只给「下一件推荐装备」一键买。
- 回城读条 3.5 秒会被伤害打断；泉水快速回血并驱逐敌人；治疗术 60 秒冷却。
- 野区四个营地 + 下游河道的「镇河铁牛」（2:30 现身），击杀者全队 75 秒增益。
- 站定不动时自动攻击射程内的敌人，但不会主动打塔下的敌将或没有兵线的塔。
- 逐鹿模式十二位君王全部可选（起始四位全是近战）；胜利仍会为王朝模式解锁下一位君王。

## 操作

- 键鼠：WASD 移动；J / 空格 / 鼠标左键攻击；Q E R 技能（**按住出指示器并跟随鼠标，松开释放**）；B 回城；F 治疗；G 买装；Tab 战绩；P / Esc 暂停。
- 触屏：左摇杆；右下攻击键 + 三个技能键（**按住拖动瞄准，松开释放；点一下自动瞄准**）；「兵」「塔」优先攻击键。
- 「托管」按钮让 AI 代打，回归测试也用它。

## 平衡口径（2026-11-15）

平衡完全靠 `sim.ts` 的 AI 对 AI 整局来量，固定种子、结果确定。

- 初版：16 局 4–4 平手但 8–19 分钟一局、场均约 20 次击杀——太慢。
  改动：英雄生命约 −15%、技能伤害 +15%、塔与鼎生命下调、兵线间隔 24 → 22 秒、攻城车加密、8 分钟后小兵加速成长。
- 现状：回归脚本的 16 局 **蓝 5 : 红 11，平均 12.1 分钟（8.1–15.9），场均 25 次击杀**；
  另一组 40 局为蓝 19 : 红 21。地图严格镜像，阵营差异是阵容抽签的波动（16 局时标准差约 2 局）。
- 英雄：40 局样本里胜率从 29% 到 74%，每位英雄 24–40 局，抽样误差约 ±9 个百分点。
  坦克与战士已收敛到 43–60%；法师与射手仍有离群。**改一个数值会让别的英雄胜率大幅摆动**（同职业互为零和），
  所以不要对着单次结果反复微调——换种子或加局数再判断。
- 难度：让 AI 托管玩家英雄各打 12 局，**新兵 12/12、校尉 7/12、名将 1/12**。
  也就是说打得和 AI 一样的人在校尉五五开；名将需要明显强于 AI 的操作。

## 验收（2026-11-15）

`node .claude/skills/verify/v3-arena.mjs`（`--quick` 只跑 6 局）：

1. 数据：塔与兵线镜像、12 位君王 36 个技能定义完整、出装表里的装备都存在、兵线上没有树。
2. 规则：移动与树木碰撞、普攻锁定、站定自动还击、大招等级锁、**36 个技能逐个施放并确认产生效果**、
   塔的仇恨与偷塔减伤、大鼎保护与胜负、回城打断、击杀赏金与重生、装备、同种子确定性。
3. 整局：16 局全部分出胜负、两边都能赢、平均时长在 6–15 分钟；难度分档有效。
4. 浏览器：真实键盘事件驱动 `ArenaGame`（移动、技能、买装、暂停）；
   桌面与手机横屏从大厅走到对战并点技能、买装、暂停、托管；页面不横向溢出；控制台零报错。

另以一次性脚本确认：整局打到结算、战绩写入、胜利解锁君王、再战一局、放弃返回大厅（结果见提交信息）。

## 已知限制 / 交接

- **没有真人试玩过。** 无头浏览器用 CPU 渲染，团战时只有 3–8 帧，手感与帧率无法在这里判断。
  十名骨骼英雄 + 阴影是主要开销；若手机吃力，先降 `render.ts` 构造函数里的像素比上限与阴影贴图尺寸，
  或让远处英雄不投影。
- AI 是简单的状态机（撤退 / 守家 / 兵线 / 交战），不会打野、不会抱团推进、不会蹲草，偶尔会站位发呆。
- 没有战争迷雾与草丛；野怪只有营地与铁牛；装备 8 件、每人最多 6 件、不可出售。
- 竖屏可玩但视野窄，横屏体验更好。
- v3 的包体因此再增加（three.js 已在包内，主要是新代码）；构建时的大包告警是已知的。

## 手感与流畅度（2026-11-15 晚）

用户反馈「不够流畅、技能不够吸引人」。这次第一次在**真实 GPU**（Apple M3，Metal）上量帧，而不是此前的 CPU 软渲染。
要点：**先测再改，每个卡顿都找到了具体原因**，下面每条都有改前改后的数据。

### 流畅度：四个具体病因
| 现象 | 原因 | 修法 | 结果 |
|---|---|---|---|
| 走路一顿一顿 | 模拟固定 60 Hz 步进，与显示器帧不同步：28% 的帧英雄**不动或走两步** | `game.ts` 改为按真实帧时长推进（单步上限 1/30 秒） | 240 帧中 240 帧位移一致 |
| 镜头发「黏」 | 镜头插值追英雄，看起来像延迟 | 活着时镜头锁死英雄，只有阵亡转镜才缓动 | — |
| 0:15 卡 160 ms | 第一下命中时才 `new AudioContext()`；用 CPU 采样器定位到单次 `play` 162 ms | `ArenaSound.warm()` 在开局（紧接「开战」点击）建好音频与噪声缓冲 | 70 秒内零长帧，最慢 16 ms |
| 团战在 Retina 掉帧 | 2 倍像素下大量叠加光效超出 GPU 填充率（p99 33 ms，最慢 100 ms） | `render.ts` 自适应分辨率：帧长超 19 ms 降 0.25 倍，持续 4 秒宽裕再升回 | 十人同时放 30 个技能：60 fps，最慢 16.8 ms |
另外：开局时预编译全部着色器（含特效与区域标记），避免第一次放技能时的编译卡顿；脚步动画按移速加快，减少「滑步」。

量帧方法（一次性脚本，未提交）：用 Playwright 启动带 `--use-angle=metal --enable-gpu` 的 Chromium，
包装 `requestAnimationFrame` 记录帧间隔与回调耗时；卡顿用 CDP `Profiler` 采样定位到函数。
**默认的无头 Chromium 是 SwiftShader 软渲染（约 8 fps），不能用来判断流畅度。**

### 技能与打击感
- `vfx.ts`：一个实例化网格画所有光晕、一个点云画所有火花，加冲击波环、光柱、刀光弧。
- 每个技能有起手冲击波；**大招**加光柱、二次冲击波、火花，玩家自己的大招有横幅名牌（`cutin`）、0.22 秒慢动作与镜头推近。
- 区域技能倒计时圆满后**爆炸**：双环、光柱、火花、近处震屏。技能弹道有发光头与拖尾。
- 增益可见：攻击加成火焰光环、吸血红光、加速残影、攻速金光、护盾气泡、晕眩星圈、减速蓝圈、回城光柱。
- **普攻三连**：连续第三下 1.6 倍重击（大字橙色伤害、短暂顿帧）；**闪现**（C 键 / 按钮，75 秒冷却）。
- 击杀与阵亡：爆点 + 慢动作 0.45 秒；塔倒塌有碎石尘爆；补刀金币飘字；音效加入滤波噪声（挥砍、冲刺、爆炸）。
- Codex 随后加固：闪现落点避开树与塔、取消起手、撞墙不扣冷却；并为重击 / 闪现 / 补刀金币补了回归断言。

### 仍未验证
- **只在一台 M3 上量过。** 手机与更弱的显卡未测；自适应分辨率应能兜底，但未实测。
- 观感是否「吸引人」仍需真人判断；当前光效偏亮，若觉得刺眼，先调 `vfx.ts` 的 `ghost` 尺寸与 `render.ts` 的 `explode`。

## 天命卷：让每局都有选择（2026-11-16）

用户反馈「还是不好玩」，希望「能得到更多技能」。诊断：真 MOBA 的乐趣主要来自真人对手和每三十秒一次的决定
（加哪个技能、买什么、打不打）；我们的版本技能自动成长、出装一键推荐，**十分钟里几乎没有可做的决定，也看不到自己在变**。
真人对手做不到（静态托管），于是补上「决定」与「可见的成长」。

- **开局与每次升级三选一**（共约 15 次）。不暂停战斗，按 1 / 2 / 3 或点卡；积压的选择会排队。
  - **技能精进**：三个技能各三阶；每阶伤害 +25%、范围 +12%、冷却 −8%。**第三阶觉醒改变形态**（按主效果类型）：
    弹道多射两道并贯穿、扇形大开并晕眩、爆炸后留灼烧地、冲锋更远并撞晕、区域暴涨、增益延长并惠及友军、闪现落地震爆。大招卡在 4 级后才出现。
  - **自动武学**（拿到就自己出手，每局最多三门、各三阶）：飞剑、雷法（三阶连锁）、箭雨、火环、寒霜（三阶冻住）、战鼓、亲兵（召出兵推线）、护体。
  - **心法**：会心、嗜血、疾行、强体、连击、凝神、聚财。
- 第一张卡必为技能或武学；**敌我 AI 同样抽卡**（多半拿第一张），所以不是玩家单方面变强。
- 代码：`arena/growth.ts`（卡池、觉醒、出牌，纯函数）；`sim.ts` 只多了英雄成长状态、`pick` / `grant` / `aiPick` 与 `runAutos`。
- 平衡：抽卡让对局从 13 分钟缩到约 8 分钟（亲兵推塔快），故塔与鼎生命上调（外塔 4800、内塔 5800、鼎 8200）。
  回归脚本现状：16 局蓝 9 : 红 7、平均 9.0 分钟、场均 29 次击杀；同样托管打法新兵 7/8 胜、名将 4/8 胜。
- 回归新增「天命卷」一节：开局三选一、升级补选、大招前不出大招卡、36 个技能觉醒后均有变化且不变弱、
  8 门武学各自六秒内生效、心法改属性、AI 整局持续成长。

调参入口：觉醒效果在 `growth.ts` 的 `tuneSkill`；武学伤害系数 `sim.ts` 的 `autoPower`（0.3×攻击 + 12×等级，按阶 ×1 / 1.5 / 2.1）；
卡牌权重在 `candidates`。真人试玩仍是唯一能判断「好不好玩」的方法。

## 自动锁定（2026-11-16）

用户反馈「角色应该自动指向攻击，不然很难打中」。原先键盘 Q/E/R 一按下就跟随鼠标瞄准，鼠标没对准就打空。改成与品类一致：
- **技能轻点 = 自动瞄准**：按键或技能键在 0.22 秒内松开，朝最佳目标释放（敌将优先、血少且近者优先，没有敌将才打小兵 / 野怪），
  弹道与延时爆炸按目标速度**提前量**。按住超过 0.22 秒（键鼠）或拖动技能键（触屏）才是手动瞄准；指示器在轻点时也会预先显示自动目标。
- **普攻键**：锁定范围内的敌将优先于更近的小兵；已锁小兵时敌将进入范围会**改锁**；不会为了追一个躲在无兵线敌塔下的敌将而把你拖进塔。
- **站定不动**：射程外 110 以内的小兵 / 安全的敌将会自动上前一步去打。
- 场上实心红环是已锁目标，半透明红环是「现在按普攻会锁谁」。
- 代码：`sim.ts` 的 `bestTarget` / `autoAim` / `lockCandidate`；`game.ts` 的 `manual()` 区分轻点与按住。回归新增「自动锁定」一节。
