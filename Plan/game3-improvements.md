# v3《鼎革：王朝崛起》— 机制诊断与改进计划

## 背景
v3 的题材、美术方向与文案都很好，但**机制层是空的**：数值会动，却几乎不影响任何结果。
玩家实际体验接近「一本带数字的电子书」——每次抉择都没有真正的代价，因此也没有张力和重玩动力。

以下每一条都在 `src/game3/App.tsx` 中经代码验证，不是主观感觉。

---

## 一、诊断（附代码证据）

### 1. 12 位君王完全是装饰品 ⭐ 最严重
`Monarch` 定义了 `passive` / `active` / `trait`，但全代码中这三个字段**只出现在大厅显示**，
从未参与任何计算：

```
grep -o "monarch\.\(passive\|active\|trait\)" App.tsx   →  各出现 1 次（均在 lobby JSX）
```

后果：嬴政与刘邦玩起来完全一致。「选君主」是本作招牌，实际却不存在，直接抹掉了重玩动力。

### 2. 六种资源里有两种是死数据
`stability`（稳定）与 `silver`（银两）**从未被任何判定读取**（无任何 `> < >=` 比较）。
其余四种也仅在最后一个事件被检查一次。中途粮草归零、民心崩盘都没有任何后果
→ 玩家怎么选都无所谓，决策没有压力。

### 3. 胜利条件形同虚设
```ts
const enough = current.army >= 45 || current.morale >= 65 || current.prestige >= 55
```
三选一即可，而兵力极易堆到 45 → 近乎必胜。

### 4. 倒计时是假的
UI 显示 10 分钟倒计时，但 `elapsed` 仅在 `> 480` 时变红，**耗尽不触发任何后果**；
且 20 次抉择 × 18 秒 = 360 秒，永远走不到 600。属于会误导玩家的 UI。

### 5. Bug：「可能中道崩殂」实为 100% 必死
`death` 字段**从未被读取**（`grep -c "\.death"` → 0）。代码靠把 `city` 改成字符串
`'中道崩殂'` 来触发死亡画面。文案写「可能」，实际选了必死。

### 6. 阶段挑战是纯掷骰子
`Math.random() >= option.success` 失败即整局结束，玩家毫无能动性；
而安全选项成功率 82–90% 且收益不差 → 理性玩家永远选安全，赌博机制自我废除。

### 7. 收集物无作用
人才 / 配偶 / 军制会被记录并显示，但不影响任何数值或结局。

### 8. 83% 的事件是模板生成
`generatedEvents` 由 `Array.from({ length: 83 })` 生成，标题即「乱世传闻 · 37」，
正文仅替换城市名。一局抽 20 个，玩家很快看穿。文本游戏的命脉是文本。

## 二、改进计划（按性价比排序）

| 优先级 | 改进 | 状态 |
|---|---|---|
| 🥇 P1 | **让君王真正生效**：12 条被动 + 每局一次的专属抉择 | ✅ 已完成 |
| 🥈 P2 | **让资源长牙齿**：断粮→军队溃散；民心尽失→民变；失稳→贪墨 | ✅ 已完成 |
| 🥉 P3 | **多结局**：武功之世 / 仁政之世 / 万邦之世 + 两种失败结局 | ✅ 已完成 |
| P4 | **挑战可被影响**：成功率随兵力/粮草/威望/内政浮动；失败改为重罚 | ✅ 已完成 |
| P5 | **修 bug + 真倒计时**：death 改 35% 真概率；时限 480 秒真会输 | ✅ 已完成 |
| P6 | **解锁系统**：初始 4 位君王，通关解锁其余 | ⬜ 待做 |
| P7 | **逐步手写事件**替换 83 个模板事件 | ⬜ 待做（持续投入） |

### 已完成部分的实测结果
- 随机乱选 6 局 → **3 胜 3 败**（此前近乎必胜），且能打出「新朝已立 · 武功之世」等不同结局
- 君王专属抉择、资源危机、时限耗尽结局均已在无头浏览器中触发验证，控制台无报错
- 平衡调整：时限初设 420 秒过严（19 次抉择即超时、出错必输），改为 **480 秒**留出容错

## 三、实施方式（降低协作冲突）

v3 由 **tim.lu** 创建。为尽量不与其开发撞车：

- **机制集中在新文件 `src/game3/rules.ts`**（君王效果、资源危机、结局判定、挑战修正），
  `App.tsx` 仅做最小接入。
- **完全不改动其事件文案**（`authoredEvents` / `generatedEvents` / `CHALLENGES` 原样保留）。
- 冲突面因此仅限于 `App.tsx` 的少数几行。

## 四、验收方式
- `npx tsc --noEmit && npm run build` 全绿（三个游戏共用一次类型检查）。
- Playwright 无头验证：不同君王的 passive 产生不同数值结果；粮草归零触发危机；
  三种结局分别可达；挑战成功率随资源变化；控制台无报错。
- 推送后等待 Pages 部署成功，确认 `/Game/v3/` 正常。
