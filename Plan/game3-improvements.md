# v3《鼎革：王朝崛起》— 机制诊断与改进计划

## 背景
v3 的题材、美术方向与文案都很好，但**机制层是空的**：数值会动，却几乎不影响任何结果。
玩家实际体验接近「一本带数字的电子书」——每次抉择都没有真正的代价，因此也没有张力和重玩动力。

以下每一条都在 `src/game3/App.tsx` 中经代码验证，不是主观感觉。

---

## 一、诊断（附代码证据）

### 1. 12 位君王完全是装饰品 ⭐ 最严重
`Monarch` 定义了 `passive` / `active` / `trait`，但全代码中这三个字段**只出现在大厅显示**，
从未参与任何计算：

```
grep -o "monarch\.\(passive\|active\|trait\)" App.tsx   →  各出现 1 次（均在 lobby JSX）
```

后果：嬴政与刘邦玩起来完全一致。「选君主」是本作招牌，实际却不存在，直接抹掉了重玩动力。

### 2. 六种资源里有两种是死数据
`stability`（稳定）与 `silver`（银两）**从未被任何判定读取**（无任何 `> < >=` 比较）。
其余四种也仅在最后一个事件被检查一次。中途粮草归零、民心崩盘都没有任何后果
→ 玩家怎么选都无所谓，决策没有压力。

### 3. 胜利条件形同虚设
```ts
const enough = current.army >= 45 || current.morale >= 65 || current.prestige >= 55
```
三选一即可，而兵力极易堆到 45 → 近乎必胜。

### 4. 倒计时是假的
UI 显示 10 分钟倒计时，但 `elapsed` 仅在 `> 480` 时变红，**耗尽不触发任何后果**；
且 20 次抉择 × 18 秒 = 360 秒，永远走不到 600。属于会误导玩家的 UI。

### 5. Bug：「可能中道崩殂」实为 100% 必死
`death` 字段**从未被读取**（`grep -c "\.death"` → 0）。代码靠把 `city` 改成字符串
`'中道崩殂'` 来触发死亡画面。文案写「可能」，实际选了必死。

### 6. 阶段挑战是纯掷骰子
`Math.random() >= option.success` 失败即整局结束，玩家毫无能动性；
而安全选项成功率 82–90% 且收益不差 → 理性玩家永远选安全，赌博机制自我废除。

### 7. 收集物无作用
人才 / 配偶 / 军制会被记录并显示，但不影响任何数值或结局。

### 8. 83% 的事件是模板生成
`generatedEvents` 由 `Array.from({ length: 83 })` 生成，标题即「乱世传闻 · 37」，
正文仅替换城市名。一局抽 20 个，玩家很快看穿。文本游戏的命脉是文本。

## 二、改进计划（按性价比排序）

| 优先级 | 改进 | 状态 |
|---|---|---|
| 🥇 P1 | **让君王真正生效**：12 条被动 + 每局一次的专属抉择 | ✅ 已完成 |
| 🥈 P2 | **让资源长牙齿**：断粮→军队溃散；民心尽失→民变；失稳→贪墨 | ✅ 已完成 |
| 🥉 P3 | **多结局**：武功之世 / 仁政之世 / 万邦之世 + 两种失败结局 | ✅ 已完成 |
| P4 | **挑战可被影响**：成功率随兵力/粮草/威望/内政浮动；失败改为重罚 | ✅ 已完成 |
| P5 | **修 bug + 真倒计时**：death 改 35% 真概率；时限 480 秒真会输 | ✅ 已完成 |
| P6 | **解锁系统**：初始 4 位君王，通关解锁其余 | ✅ 已完成 |
| P8 | **让收集物生效**（原诊断第 7 条）：人才 / 军制 / 配偶各带常驻加成 | ✅ 已完成 |
| P9 | **军需消耗**：军队每回合吃粮，粮草第一次成为真正的约束 | ✅ 已完成 |
| P7 | **逐步手写事件**替换 83 个模板事件 | ⬜ 待做（持续投入） |

### P6 解锁系统（`src/game3/meta.ts`）
- 初始只给 4 位：**刘邦 / 李世民 / 朱元璋 / 曹操**（草根、明君、开国、枭雄四种玩法）
- 每通关一次按固定顺序解锁下一位：赵匡胤 → 刘彻 → 武曌 → 朱棣 → 司马懿 → 忽必烈 → 铁木真 → 嬴政
- 存档键 `dingge:v3:meta`，记录 `unlocked / wins / runs / reigns`（国号也做成收集品）
- 大厅改为 12 格名录，锁住的显示 🔒 并提示「下一位待解锁」

### P8 朝堂加成（原诊断第 7 条，之前遗漏）
人才 / 军制 / 配偶原本只被记录和显示，不影响任何数值。现在三者各带一条常驻加成：
- **11 位人才**各一条（诸葛亮每回合稳定 +2、郑和每回合银两 +3、郭子仪挑战失利损失减半……）
- **5 种军制**（农民军军需减半但兵力收益 -10%、火器新军攻势挑战 +12% 但军需 +1……）
- **6 位配偶**，且开局改为**「尚未成家」**——联姻因此成为真抉择，而不是白送的加成
- 侧栏新增「朝堂加成」面板，把生效中的条目直接列出来，让玩家看得见机制在起作用
- 挑战奖励现在也走君王被动 + 朝堂加成（此前大关是机制的真空地带）

### P9 军需消耗
`upkeepFor()`：每回合消耗 `floor(兵力/22)` 粮草，受军制/人才/配偶修正，**有兵则至少 1**
（否则「张居正 + 农民军」会得到完全免费的军队）。资源条直接显示「军需 -N/回合」。

### 本轮修掉的两个真实 bug
1. **结局判定不公平**：`Math.max(army, morale, prestige)` 拿**无上限的兵力**去和封顶 100 的
   民心/威望比大小 → 兵力几乎永远胜出，14 局实测「仁政之世」**一次都没出现**。
   改为比较各自**超出立国门槛的倍数**（army/55、morale/60、prestige/55）。
2. **倒计时被 CSS 隐藏**（`.timer { display: none }`）：P5 让时限变成真会输的机制，
   玩家却完全看不见剩余时间。已恢复显示并加上告急状态。
3. 附带修掉断粮的**死亡螺旋**：危机把粮草重置到 4，而军需每回合要 3–5 → 下回合必然再次断粮。
   改为重置到 12（溃散的士卒也带走了自己那份口粮）。

### 实测结果
- 随机乱选 20 局 → **10 胜 10 败**（最初版本近乎必胜）；另一轮 16 局 → 9 胜 6 败 1 崩殂
- **6 种结局全部可达**：万世之基（新增最高结局）/ 马上得天下 / 民心所归 / 万邦来朝 /
  天命未成 / 乱世吞没了你，另加中道崩殂
- 解锁链完整跑通：8 次通关 → 12 位君王全解锁，`localStorage` 存档正确，控制台零报错
- 平衡调整：时限初设 420 秒过严（19 次抉择即超时、出错必输），改为 **480 秒**留出容错

### 新增最高结局：万世之基 · 开元之世
条件：三根支柱立住两根 + （4 座城 或 4 位贤才）+ 稳定 ≥ 45。
这让「城池」和「人才」两类收集物第一次进入胜负判定，也给熟练玩家一个可追的目标。

## 三、实施方式（降低协作冲突）

v3 由 **tim.lu** 创建。为尽量不与其开发撞车：

- **机制集中在新文件 `src/game3/rules.ts`**（君王效果、朝堂加成、军需、资源危机、结局判定、挑战修正）
  与 **`src/game3/meta.ts`**（解锁存档），`App.tsx` 仅做最小接入。
- **完全不改动其事件文案**（`authoredEvents` / `generatedEvents` / `CHALLENGES` 原样保留）。
- 冲突面因此仅限于 `App.tsx` 的少数几行。

## 四、验收方式
- `npx tsc --noEmit && npm run build` 全绿（三个游戏共用一次类型检查）。
- Playwright 无头验证：不同君王的 passive 产生不同数值结果；粮草归零触发危机；
  三种结局分别可达；挑战成功率随资源变化；控制台无报错。
- 推送后等待 Pages 部署成功，确认 `/Game/v3/` 正常。
